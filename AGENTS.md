# Repository workflow

Read `CONTRIBUTING.md` before committing, pushing, or opening a PR.

- Work on a feature branch. If starting on `main`, create a branch before making changes or commits.
- Submit changes through a PR targeting `main`; never push directly to `main`.
- Run checks appropriate to the change and report remaining validation honestly. Wait for `LifeOR2 validation` before merging.
- Do not merge a PR unless the user authorizes merging. Use squash merge and resolve review conversations first.
- GitHub protection applies to administrators too. Do not bypass or weaken it to merge changes.

Product and implementation conventions are in `CLAUDE.md`.
